# Веб-панель hls-grabber

Локальний сервер із вбудованим інтерфейсом. Як користуватись — у
[README](README.md), тут про будову.

## Збірка й запуск

```powershell
go build -ldflags "-H=windowsgui" -o build/bin/hls-grabber-web.exe ./cmd/web
.\hls-grabber-web.cmd
```

`.cmd` шукає `build/bin/hls-grabber-web.exe`, а якщо не знаходить — запускає
`go run ./cmd/web`. Тобто після `git clone` він працює й без попередньої
збірки, просто повільніше стартує.

Інший порт:

```powershell
.\hls-grabber-web.cmd --port 8790
```

Увесь інтерфейс — шрифти, стилі, скрипти, бібліотека анімацій — вшитий у виконуваний файл через
`go:embed`. Тому зібраний `.exe` не потребує ні Node, ні Python, ні
інтернету.

## Будова

```
cmd/web/

├── extension.go    розпакування розширення для Firefox

```

### Інтерфейс

Три колонки: навігація, робоча сторінка і черга праворуч. Медіатека —
покроковий майстер (сторінка → озвучки → серії), ручні посилання — окрема
вкладка. Нижче 1280 px черга ховається в міні-плеєр, нижче 640 px
навігація переїжджає вниз.

Уся розмітка стилів в одному файлі — `webui/ui.css`. Кольори лежать
змінними в `:root`, тож тему міняти звідти.

Рух — через Motion (`webui/vendor/motion.js`, глобальний `window.Motion`).
Усі виклики йдуть через `animate()` в `app.js`: якщо бібліотека не
завантажилась або в системі ввімкнено «менше руху», панель працює так само,
лише без анімацій. Оновлюючи Motion, бери `dist/motion.js` з npm-пакета
`motion` і онови версію тут.

## Розширення Firefox

Живе в `browser-extension/` і вшивається в панель. Установлення —
**Діагностика → Firefox Bridge**: панель розпакує файли в
`%LOCALAPPDATA%\hls-grabber\browser-extension` і відкриє `about:debugging`.

Firefox вимагає підпису Mozilla для постійного встановлення, тож локальна
збірка вантажиться тимчасово — до перезапуску браузера.

Змінив файли розширення — підніми версію в `manifest.json` і `assets.go`.
Панель звіряє вшиту версію з підключеною й лається в Діагностиці, якщо у
Firefox лишилась стара збірка. Без цього оновлення просто не подіє, і
зрозуміти чому буде важко.

### Файли розширення

| Файл | Що робить |
|---|---|
| `service-worker.js` | Фон: ловить плейлисти, забирає команди панелі, відкриває фонові вкладки. |
| `content-script.js` | Обхід сторінки: озвучки, сезони, епізоди. |
| `cdn-api.js` | Прямі звернення до `ajax/get_cdn_series` — головний шлях. |
| `stay-awake.js` | Переконує сторінку, що вкладка видима: без цього плеєр не вантажить відео у фоні. Потрібен лише запасному шляху через плеєр. |
| `popup.js` | Ручний запуск обходу з відкритої сторінки. |

## Перевірка розширення

```powershell
node --test browser-extension/*.test.js
```

Перевіряє, що фоновий скрипт реєструє на СТАРТІ будильник, слухача
повідомлень і перехоплення запитів. Написано після поломки, де блок із
будильником опинився всередині функції: синтаксис лишався правильним, тож
ані збірка, ані `node --check` нічого не помітили, а міст мовчки відвалювався
через 75 секунд.

## Обмін між панеллю і розширенням

Зв'язок двосторонній, але обидва напрямки — звичайний HTTP на localhost.

```
розширення → панель    POST /api/inbox            знайдені посилання
                       POST /api/bridge/heartbeat  «я живий»
                       POST /api/bridge/result     хід і наслідок обходу
                       POST /api/bridge/resolved   свіжі адреси серії

панель → розширення    POST /api/bridge/probe      розібрати адресу
                       POST /api/bridge/scan       обійти вибрані озвучки
                       GET  /api/bridge/commands   розширення забирає накопичене
                       GET  /api/bridge/resolves   запити свіжих посилань для черги
```

Запити свіжих посилань ідуть окремим каналом (`cmd/web/resolve.go`). Черга
шле їх, коли адреса серії протухла, а обхід серіалу може тривати хвилинами.
У спільній черзі команд запит стояв би за обходом, і панель не дочекалася б
відповіді.

Черга, а не сокет: Firefox вивантажує фонову сторінку між подіями, і
постійне з'єднання довелося б піднімати після кожного пробудження.
Опитування на `chrome.alarms` — звичайні таймери вмирають разом зі
сторінкою.

## Діагностика

Сторінка перевіряє yt-dlp, ffmpeg, міст Firefox, доступність тек і місце на
диску. Звідти ж інструменти оновлюються: копії лежать у
`%LOCALAPPDATA%\hls-grabber\tools`, завантажене звіряється з контрольною
сумою видавця, і лише після цього налаштування перемикаються на нову версію.
Старі файли не видаляються.

## Залежності

Одна зовнішня залежність — `golang.org/x/sys`, для керування процесами
yt-dlp у Windows.
