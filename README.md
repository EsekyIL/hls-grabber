# hls-grabber

Качає серіали й фільми з HLS через yt-dlp і ffmpeg. Усе крутиться локально.

Автоматичний обхід уміє два сайти:

- **HDRezka** (rezka.ag і дзеркала) — через її ендпоінт `ajax/get_cdn_series`,
  з вибором якості;
- **uakino** (uakino.best і дзеркала) — через плейлист сторінки й плеєр
  ashdi. Кожен сезон там окрема сторінка, тож і розбирати їх треба окремо.

На інших сайтах обхід не запрацює. Ручний режим із прямими посиланнями бере
будь-що.

## Складові

Веб-панель (`cmd/web`) — інтерфейс у браузері: обхід сайту, черга,
діагностика. Розширення для Firefox (`browser-extension`) — міст до сайту,
вшитий у панель і встановлюваний звідти ж.

Будова описана в [ARCHITECTURE.md](ARCHITECTURE.md).

## Потрібно

Windows 10/11, Go 1.22+ для збірки, Firefox для автоматичного обходу.

PowerShell 7 не обов'язковий, але з ним вибір теки відкриває нормальний
провідницький діалог. Без нього — старе вузьке дерево тек із PowerShell 5.1.

yt-dlp і ffmpeg ставити не треба, панель качає їх сама на сторінці
«Діагностика» й звіряє контрольні суми.

## Запуск

```powershell
go build -ldflags "-H=windowsgui" -o build/bin/hls-grabber-web.exe ./cmd/web
.\hls-grabber-web.cmd
```

Панель працює без вікна консолі: `.cmd` лише запускає її й відкриває
браузер. Вимикається вона в **Діагностиці → «Вимкнути панель»**; незакінчене
завантаження продовжиться після наступного запуску. Повторний запуск, коли
панель уже працює, просто відкриває її. Що відбувається всередині, видно в
`%TEMP%\hls-grabber\download.log`.

Далі:

1. **Діагностика → Firefox Bridge → «Підключити Firefox»**. Панель розпакує
   розширення й відкриє `about:debugging`. Там «Load Temporary Add-on» і
   вибрати вже виділений `manifest.json`.
2. **Медіатека** — встав адресу серіалу, «Розібрати».
3. Познач озвучки, «Знайти посилання».
4. Вибери якість, познач серії, «Додати до черги».

Черга завжди видна праворуч: що качається зараз, швидкість, скільки
лишилось і що далі. На вузькому вікні вона згортається в кнопку з
відсотком у кутку.

Firefox тримає непідписані розширення лише до перезапуску, тож перший крок
доведеться повторювати після кожного запуску браузера. Після оновлення панелі
— теж: у Діагностиці це видно як «завантажена стара версія».

Щоб не повторювати, розширення можна підписати як непубліковане на
addons.mozilla.org (потрібні Node.js і API-ключі акаунта Mozilla):

```powershell
.\sign-extension.ps1
```

Скрипт спитає ключі, якщо їх немає в `WEB_EXT_API_KEY` / `WEB_EXT_API_SECRET`,
і покладе `.xpi` у `build\xpi`. Цей файл перетягни у Firefox, і розширення
стане постійним. Ту саму версію AMO двічі не підписує, тож після змін у
розширенні треба підняти версію.

Починаючи з 1.13.0 розширення оновлюється само. Скрипт підпису кладе `.xpi`
і `updates.json` у теку `updates/`, комітить і пушить, а Firefox раз на
добу читає `updates/updates.json` з гілки `main` і ставить новішу версію.
Не чекати можна так: `about:addons` → шестірня → «Перевірити наявність
оновлень». Версію, встановлену до 1.13.0, треба один раз замінити
вручну, бо в неї ще немає адреси оновлень.

## MPEG-TS у .mp4

З увімкненим «HLS MPEG-TS» yt-dlp пише серію як транспортний потік. Панель
після завантаження перепаковує такий файл у справжній MP4 без перекодування.
Файли, скачані старішими збірками, виправляє скрипт:

```powershell
.\remux-ts.ps1 "D:\Серіали\Назва"
```

## Проксі

**Налаштування → Проксі**: список для yt-dlp, по одному в рядку, або
«Імпорт з файлу» (.txt). Підходять `host:port`, `host:port:логін:пароль` і
`socks5://логін:пароль@host:port` (а також http, https, socks4). Панель
перевіряє список під час збереження. Якщо завантаження через проксі не
вдалось, вона бере наступний і запам'ятовує той, що спрацював. Пошук серій
іде браузером і проксі не використовує. Порожній список означає пряме
з'єднання.

## Порти

Панель і розширення за замовчуванням працюють на 8787. Якщо порт зайнятий,
підніми панель на іншому:

```powershell
.\hls-grabber-web.cmd --port 8899
```

Розширення саме знайде панель на 8787, 8899, 8788–8790, 8080, 8888 чи 9000
й запам'ятає порт. Будь-який інший треба вписати в попапі розширення.

## Пошук посилань

HDRezka віддає адреси через `ajax/get_cdn_series` — той самий ендпоінт, яким
користується її плеєр. Один запит на епізод, у відповіді всі якості від 360p
до 1080p Ultra. Плеєр не запускається.

Якщо ендпоінт недоступний, вмикається запасний шлях: розширення клацає
епізоди й ловить `.m3u8` у трафіку. Повільніше й дає одну якість.

Обхід іде у фоновій вкладці, сидіти на сторінці не треба.

## Файли

```
Videos/
├── Films/
│   ├── Назва фільму.mp4
│   └── Назва фільму (2).mp4
└── Serials/
    └── Назва серіалу/
        └── Season 01/
            └── Озвучка/
                ├── S01E01.mp4
                └── S01E02.mp4
```

Кожна озвучка лежить окремою текою, тож дві озвучки однієї серії не
затирають одна одну. Серію, яка вже є на диску, черга пропускає. Фільм із
назвою, що вже зайнята, зберігається з номером у дужках, а наявний файл
лишається як був.

Теки міняються в «Налаштуваннях».

## Збої

Сайт дає на кожну якість кілька адрес на різних CDN. Коли перша
відповідає помилкою, черга одразу пробує наступну. Якщо не вдалася жодна,
вона чекає й повторює все коло. Скільки разів і з якою паузою, задають
«Повторні спроби» й «Затримка» в «Налаштуваннях». Помилки, які повтор не
виправить (немає теки, не знайдено yt-dlp), не повторюються.

Посилання сайту підписані й з часом протухають, тож серія, яка довго
пролежала в черзі, може отримати відмову на всіх дзеркалах. Тоді черга один
раз просить у розширення свіже посилання тієї самої якості й качає вже з
нього. Для цього Firefox із розширенням має бути запущений; сторінку
серіалу розширення відкриє у фоні саме й потім закриє.

## Обмеження

Один сайт — зміниться його розмітка чи API, доведеться правити адаптер.
Тільки Windows: вибір теки й керування процесами написані під неї. Для
особистого користування; жодного відео проєкт не містить і не поширює.
